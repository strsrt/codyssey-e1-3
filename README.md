# Mini NPU MAC Simulator

표준 라이브러리만 사용하는 Python 콘솔 기반 MAC 시뮬레이터입니다.

## 실행

```console
python main.py
```

실행 직후 사용자 입력(3x3) 또는 `data.json` 분석 모드를 선택합니다.
사용자 입력 모드에서는 필터 및 패턴 각각에 대해 직접 입력 또는 Cross/X
자동 생성 중 선택합니다. 직접 입력 시 필터 A/B를 먼저 행 단위로 저장한 뒤
패턴을 입력합니다. 각 행은 공백으로 구분한 숫자 세 개를 입력하며 잘못된
행은 안내 메시지 후 다시 입력합니다. `data.json`은 `main.py`와 같은 폴더에서
읽습니다. Python 3.8 이상과 표준 라이브러리만 필요합니다.

## 데이터 구조와 JSON 스키마

`Matrix`는 정사각형 2차원 숫자 배열을 입력받아 행 우선 1차원 리스트(길이
N²)에 저장하고, `get_value(row, column)` 및 `set_value(row, column, value)`로
원소를 읽고 수정합니다. 3x3, 5x5, 13x13, 25x25를 처리합니다. MAC은 외부
라이브러리 없이 반복문으로 1차원 리스트를 순차 접근해 곱하고 누적합니다.
`generate_patterns(N)`은 중앙 행/열을 채운 Cross와 양 대각선을 채운 X를
생성합니다. 모드 1의 필터·패턴 자동 입력과 성능 측정 데이터에 재사용합니다.

JSON 최상위 객체는 `filters`와 `patterns`를 포함합니다. 필터는
`filters.size_5`, `filters.size_13`, `filters.size_25`에 크기별로 두며,
각 항목은 `cross`와 `x` 키를 가진 행렬 객체입니다. 패턴 키는
`size_{N}_{idx}` 형식이고, 각 패턴 객체는 2차원 배열인 `input`과
`expected`를 포함합니다. 패턴과 필터 입력은 행과 열의 크기가 같은
2차원 배열이어야 합니다.

## 결과 리포트

JSON 분석은 각 케이스를 개별적으로 검증하고, 한 케이스의 오류가 다른
케이스 분석이나 프로그램 종료를 막지 않도록 해당 케이스만 FAIL 처리합니다.
실패 요약에는 케이스 키와 스키마 또는 크기 불일치 사유가 표시됩니다.
`data.json` 모드의 마지막에는 전체/통과/실패 수와 실패 목록이 출력됩니다.

라벨은 내부 표준값 `Cross`와 `X` 두 가지로 정규화합니다.
expected의 `+` 및 `Cross`는 `Cross`로, expected의 `x` 및 `X`는 `X`로
변환합니다. 필터 키 `cross`/`Cross`와 `x`/`X`도 같은 표준값을 사용합니다.
따라서 대소문자 또는 기호 표기 차이만으로 PASS/FAIL이 달라지지 않습니다.

점수 차이의 절댓값이 `1e-9`보다 작으면 동점으로 분류해 `UNDECIDED`를
출력합니다. 동점 결과는 두 개의 표준 expected 라벨(Cross, X) 중 어느 것과도
같지 않으므로 해당 expected를 가진 케이스는 FAIL입니다. 이 epsilon 정책은
부동소수점 오차가 아주 작은 점수 차이를 승패로 과장하는 일을 방지합니다.
epsilon 이상 차이가 나면 더 큰 점수의 필터가 판정 결과가 됩니다.

실패 원인은 대체로 패턴 키의 `size_N_idx` 형식 오류, expected 라벨 오타,
필터 키의 누락, 비정사각형 입력, 또는 패턴과 필터의 크기 불일치입니다.
프로그램은 키에서 N을 추출해 해당 `filters.size_N`을 고르고 행렬 크기도
검증하므로 잘못 연결된 크기를 조용히 계산하지 않습니다. 현재 예제 데이터는
`+`/`x` 별칭을 정규화하고 각 크기와 행렬을 맞춰 두어 세 케이스 모두
PASS가 됩니다. 즉, 실패가 0인 이유는 라벨 정책과 입력 스키마가 맞기 때문이며
잘못된 입력을 무시해서가 아닙니다.

## 성능 및 시간 복잡도

성능 분석은 모드 1에서 3x3을, JSON 모드에서 3x3/5x5/13x13/25x25를
측정합니다. 각 크기에서 같은 생성 패턴/필터를 사용해 기존 2차원 중첩 접근
(`mac_2d`)과 최적화된 1차원 연속 접근(`mac`)을 각각 1,000회 실행합니다.
표에는 크기, 각 구현의 평균 시간(ms), 속도비(2D/1D), N² 원소 연산 횟수가
표시됩니다. 데이터 생성 및 1D/2D 변환은 타이머 구간 밖에 두어 MAC 함수 호출
시간만 비교합니다. 각 쌍은 동일한 값의 행렬과 같은 반복 횟수를 사용합니다.

성능표는 실행할 때 측정되어 표시되므로 기기와 Python 상태에 따라 달라집니다.
1D/2D 속도비가 1보다 크면 해당 실행에서 1D 경로가 더 빨랐다는 뜻입니다.
작은 N에서는 함수 호출 및 타이머 오버헤드가 차이를 가릴 수 있으므로 표의
값은 환경별 관찰 결과로 해석합니다. 같은 입력·횟수로 비교하므로 크기별
두 열 간 비교는 가능하지만, 한 번의 측정으로 모든 환경의 속도를 보장하지는
않습니다.

한 패턴과 한 필터의 MAC 연산은 각 원소를 정확히 한 번씩 방문하므로 시간
복잡도는 O(N²)입니다. 두 필터 판정은 MAC을 두 번 수행하므로 여전히
O(N²)이며 상수 계수만 증가합니다. 성능표의 연산 횟수는 N=3, 5, 13, 25에서
각각 9, 25, 169, 625입니다. N을 2배로 늘리면 각 입력의 원소 수가 4배로
증가하는 것이 이 복잡도의 근거입니다. 평탄화는 연산 횟수를 줄이지 않고
행/열 인덱싱과 중첩 리스트 접근을 단순화하는 메모리 접근 최적화입니다.
입력 행렬 및 평탄화된 데이터는 O(N²) 공간을 사용하고 MAC 누적기는 O(1)
추가 공간을 사용합니다.
